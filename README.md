# OptiNexus AI — Independent Deployment

OptiNexus AI is a React + Vite frontend with a FastAPI backend, MongoDB Atlas database,
Google Gemini API integration, scientific literature search, PDF extraction and analysis,
page-cited document Q&A, projects, notes, citations and academic writing tools.

## Stack

- Frontend: React 19 + Vite + Tailwind CSS
- Backend: Python FastAPI
- Database: MongoDB Atlas
- AI: Google Gemini API (`GEMINI_API_KEY`)
- Hosting: Render (frontend static site + backend web service)

## 1. Configure MongoDB Atlas

1. Create a MongoDB Atlas project and free cluster.
2. Create a database user and password.
3. Add the Render outbound IP access rule or, for initial testing, use the Atlas network access setting appropriate to your security requirements.
4. Copy the connection string. URL-encode special characters in the database password.
5. Use database name `optinexus`.

## 2. Get a Gemini API key

Create an API key in Google AI Studio and store it only in the Render backend environment as `GEMINI_API_KEY`.
Never put the key in React/Vite environment variables or commit it to Git.

## 3. Deploy with Render Blueprint

1. Push this repository to a private GitHub repository.
2. In Render, choose **New → Blueprint** and connect the repository.
3. Render reads `render.yaml` and proposes two services: `optinexus-api` and `optinexus-web`.
4. Enter `MONGO_URL` and `GEMINI_API_KEY` when prompted. `JWT_SECRET` is generated by Render.
5. Deploy both services.
6. After the services are created, copy the backend URL and frontend URL. The Blueprint wires `VITE_API_URL` from the backend service URL.
7. Update backend `CORS_ORIGINS` to the frontend Render URL and any custom domain, separated by commas. Redeploy the backend after changing it.

## 4. Connect your domain

1. In the Render static site settings, add your domain (for example `optinexus.ai`).
2. Add the DNS records Render provides at your domain registrar.
3. Wait for DNS verification and HTTPS certificate provisioning.
4. Add the custom domain to backend `CORS_ORIGINS` and redeploy the backend.

## 5. Local development

Backend:
```bash
cd backend
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn server:app --reload --port 8001
```

Frontend (in another terminal):
```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

Set `VITE_API_URL=http://localhost:8001` in `frontend/.env`.

## Environment variables

Backend:
- `MONGO_URL` — required MongoDB Atlas URI
- `DB_NAME` — database name, e.g. `optinexus`
- `JWT_SECRET` — long random signing secret
- `GEMINI_API_KEY` — Google Gemini API key
- `CORS_ORIGINS` — comma-separated frontend origins
- `CONTACT_EMAIL` — optional contact for OpenAlex/Crossref
- `NCBI_API_KEY` — optional higher PubMed rate limit

Frontend:
- `VITE_API_URL` — public backend base URL, without trailing slash

## Notes and limitations

- AI usage is billed separately by Google according to the selected Gemini model and account terms.
- Render free web services may sleep when idle and take time to wake. Choose a paid instance if you need always-on service.
- MongoDB Atlas free cluster has storage and throughput limits; review current Atlas limits.
- This project stores extracted PDF text/chunks in MongoDB. Original uploaded PDF files are not retained for later download.
- Configure backups for your MongoDB database before production use.
- Use a strong `JWT_SECRET`; never commit `.env` files or API keys.
- The app uses bearer-token authentication, so the API CORS configuration does not enable credential cookies.

## Health check

After deployment, visit `https://YOUR-API.onrender.com/health`. It should return `{"status":"ok","service":"optinexus-api"}`.

## Build fixes (second repair)

- `npm install` failed with `ERESOLVE` because `react-day-picker@8` needs `date-fns` 2 or 3. `date-fns` is now `3.6.0`, and `frontend/.npmrc` sets `legacy-peer-deps=true` (React 19 vs. the day picker's peer range).
- `npm run build` failed because Vite cannot parse JSX in `.js` files. `App.js`, `index.js` and `context/AuthContext.js` are now `.jsx`, and `index.html` points to `/src/index.jsx`.
- `vite` and `@vitejs/plugin-react` were set to `latest`, which pulled in a Vite major that breaks this setup. They are now pinned (`5.4.11` / `4.3.4`).
- The backend now explains missing/placeholder `MONGO_URL` or `JWT_SECRET` in plain words, and no longer crashes at startup if MongoDB is unreachable (it logs the error; `/health` still answers). Fix `MONGO_URL` / Atlas "Network Access" if login or registration fails.
- Tests: `pip install -r requirements-dev.txt` (the pytest config needs `pytest-xdist`).
- Local frontend: set `VITE_API_URL=http://localhost:8001` in `frontend/.env`, and run the backend on port 8001.
